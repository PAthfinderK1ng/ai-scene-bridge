# 06 · 场景程序（v5）：让 AI 自己搭结构

> 2026-10-19，用户用 v4 说「我要生成魔法学院」，三张卡是「塔院学院 / 谷桥学院 / 环院学院」——名字变了，**空间还是那三样**：坡上台地、溪谷两岸、一圈圈的环台，房子还是撒小方块。用户：「永远就这几个预设，不行啊，我要 AI native」。
> 本文替代 docs/05 的 plan 格式（v4 的构成图），其余（说 → 选 → 改 → 出、本地操作不花钱、导出 / 读回、空间内部布局）不变。

## 0. 为什么 v4 还是预设

| 原因 | 证据 |
| --- | --- |
| 地形词表是「台地型」的 | `terrain.type` 只有 hill / ridge / slope_terraces / ring_terraces / plateau / cliff / valley / basin / pit / island——任何题材都被翻译成台地 |
| 「区域 → 撒房子」是唯一的建筑生成方式 | zones 只能 use=housing 等，引擎在台地上铺小盒子；学院、神殿、港口、城堡都长成村子 |
| 建筑只有「类型 + 一个尺寸」 | form 是 house / tower / hall … 的盒子或圆柱，没有组合、没有屋顶以外的形体 |
| 提示词示例全是山村 | `prompt_examples(2)` 取最短的两个示例，都是山村；模型照抄结构 |

结论：v4 开放了**名字**，没有开放**结构**。

## 1. 原则（这一版的变化）

- **AI 自己搭结构**：AI 写一段**场景程序**——用形体（盒、圆柱、圆锥、穹顶、拱、墙、台阶、桥、平台、浮岛、水、树、岩、晶体 …）组成组，组可以嵌套、**重复**（直线 / 网格 / 环形 / 沿路 / 随机散布 / 镜像 / 叠层）、相对彼此定位；地形用**雕刻操作**（抬起、压低、削平、台阶化、坡道、开沟、成湖、立崖）组合出来。
- **坐标规则改成「局部尺寸与偏移可以写，全局摆放交给引擎」**：AI 可以在自己的组里写米制的尺寸、偏移、旋转、间距、半径（像建筑师画草图）；组放在场地上的哪里用**锚点**（`site.N`、`hall.top`、`moat.inner`…）表达，引擎负责落地（贴地 / 悬空）、避让（重叠时推开并报告）、路由（路 / 桥 / 台阶）、检查（看得见、到得了、不压、不悬空）。依据：LLM 写一长串全局坐标容易错，但写结构化的局部关系、重复与对称（像写代码）很擅长；错误由引擎检查和画面反馈兜住。
- **三张卡 = 三个不同的空间概念**：先构思三个概念（一句话 + 关键结构 + 地形想法），再分别展开成程序；概念之间必须在**空间组织方式**上不同（散布 / 轴线 / 水网 / 残骸 / 环形 / 下沉 / 垂直 / 悬空 … 从题材里长出来，不套「一个往上、一个在水上、一个往地下」的三分法），不是同一结构换名字。
- **村子只是一种可能**：「台地」「撒房子」「迷宫 / 矿道」变成程序里可选的**生成器节点**，题材需要才用。

### 2.1 节点类型

| 类 | type | 关键字段 |
| --- | --- | --- |
| 形体 | `box` `cylinder` `cone` `dome` `pyramid` `wedge` `arch` `torus` `sphere` `prism`（n 边柱） | `size_m`（按形体：[宽,高,深] / [直径,高] / [直径]），`sides`（prism），`hollow`（拱、环） |
| 建筑件 | `building`（盒 + 屋顶 gable / hip / flat / dome / spire / none，`floors`）、`tower`（圆或方柱 + 屋顶）、`wall`（沿局部折线 `path_m: [[x,z],…]` 或 `around: <id>`，高、厚，`gate`）、`courtyard`（围合院，`gate` 方向）、`stairs`、`platform`、`column`、`gate`、`statue`、`tree`、`rock`、`crystal`、`island`（悬空岩块，`elev_m`）、`water`（池 / 渠，局部形状） | `label` 随便起；`color`（色板角色）；`material`（一句话） |
| 组合 | `group`（`children`）、`repeat`（`pattern`: `linear` `grid` `radial` `along` `scatter` `mirror` `stack`；`count` `spacing_m` `rows` `cols` `radius_m` `start_deg` `face`（`center` / `out` / `path`）`along`（link id）`area`（节点 id / 地形 id）`axis`（mirror：x / z）`levels`（stack）`child`） | `child` 可以是任何节点（含 group / repeat） |
| 连接 | `link`（`style`: `path` `road` `stairs` `ramp` `bridge` `rope_bridge` `tunnel` `canal` `portal`；`from` `to` `via`；`width_m`） | 引擎路由（路 / 台阶走地形，桥直线跨越，隧道走地下，传送门只画标记） |
| 生成器 | `terraces`（坡上台地 / 环台：v4 的算法）、`scatter_houses`（在区域里按密度撒 `building` 模板：v4 的 zones）、`space`（地下 / 空中空间 + 内部布局：v4 的 interior）、`grove`（树林）、`field`（田块） | 题材需要才用 |

- **定位**：`at` = 锚点（`site.<C|N|NE|…>`、`<id>`、`<id>.<top|bottom|center|N|S|E|W|NE|…|inner|outer>`、`<repeat id>[k]`）；`offset_m` = 在父组局部坐标里的偏移 `[dx, dz]` 或 `[dx, dy, dz]`；`rotate_deg`；`elev_m` = 离地高度（> 0 即悬空）；`ground: "snap" | "float" | "carve"`（贴地 / 悬空 / 嵌入地下）。
- **没有全局坐标**：根节点必须用 `at` 锚到 `site.*` 或地形块 / 其它节点；只有组内才用 `offset_m`。
- `id` 可省（引擎补）；被引用的要写。数量上限：节点展开后 ≤ 600 个形体（repeat 展开计数），地形操作 ≤ 16 个。

### 2.2 地形雕刻（`terrain[]`）

`op`：`raise`（抬起，`height_m`，`edge`: `slope|cliff|terraced`，`steps`）、`lower`（压低 / 坑）、`flatten`（削平到锚点高度）、`terrace`（台阶化已有坡面，`steps`）、`ramp`（`from` → `to` 的坡道）、`carve`（沿线开沟 / 峡谷，`width_m` `depth_m`）、`lake`（成湖，带水面）、`river`（沿线的河）、`cliff`（立崖）、`dune`（沙丘起伏）、`noise`（`amplitude_m` `scale_m` 的自然起伏，种子化）。`shape`: `circle` `ellipse` `rect` `ring` `line`（配 `from`/`to` 或 `path_m`）`polygon_m`（局部多边形）。`at` 同节点定位。引擎把它们编译成高度场（现有 terrain.js 的叠加之上加：覆盖 / 相加 / 削平 三种合成），台阶化的面会登记成「台地」供生成器与检查使用。

## 3. 两步生成（AI）

1. **构思**（一次调用，短）：给三个**空间概念**：`[{ name, concept, key_structures: [..5 条], terrain_idea, why_different }]`。要求三者在空间组织上不同（垂直 / 水平 / 地下 / 水上 / 悬空 / 环形 / 轴线 / 散布 … 至少两种维度不同）。
2. **展开**（三次调用，**并行**）：每个概念写成一段场景程序（上面的格式）。系统提示里给的是**节点语法 + 一组小片段**（环形塔群、轴线院落、悬浮群岛、峡谷栈道、地下大厅、港口码头、台地村落……各几行），**不给整张示例**，并明说「不要默认用台地 / 撒房子，除非题材需要」。
- revise：`ops` 作用在程序树上（`set` 某节点某字段、`add` 子节点 / 根节点 / 地形操作、`remove`），按 id 找（含 `towers[2]` 这种实例引用）。
- 本地锁定照旧（说死的词三张都要有，例：「迷宫」→ 有 space.layout=maze；「浮岛」→ 有 island 节点）。

## 4. 引擎（engine/plan.js 重写为解释器）

`compilePlan(plan, { seed }) → { sid, T, checks, facts, index }`（接口不变）：
1. 场地 + 地形雕刻 → 高度场（`site.ground` 给基础形态：lake = 中间低、mountain = 中间高 …，再叠操作）。
2. 节点树**展开**（repeat 实例化、mirror、stack），每个实例得到局部变换；锚点解析（拓扑排序，环检测）；局部 → 世界。
3. **落地**：`snap` 的形体底面取下方地形高度（大形体取覆盖范围的最高点，脚下自动补基座 / 平台并在 facts 里记）；`float` 用 `elev_m`；`carve` 嵌入。
4. **避让**：同层形体重叠时，按「后来者让」沿最近方向推开（≤ 形体尺寸的一半），推不开就报告（检查里「X 与 Y 重叠」+ 修法）。
5. **连接**：link 按 style 路由（path / road / stairs / ramp 走 A*，bridge / rope_bridge 直线跨越并给桥墩，tunnel 走地下，canal 开沟，portal 只画两端标记）。
6. 生成器：terraces / scatter_houses / grove / field / space 调 v4 现有代码。
7. 检查：重叠、悬空（snap 的形体下方被挖空）、可达（spawn → 每个 landmark / 关系里的 reachable）、看得见、关系、空间检查；facts：形体数、各类计数、最高点、水面积、路长。
8. SID：volumes 的 `shape` 扩成全部形体类型（box / cylinder / cone / dome / pyramid / wedge / arch / torus / sphere / prism），带 `size`、`rotation_y`、`roof`、`elev`、`plan_id`、`instance_of`；paths 带 style；markers 带 portal；features 带 op。

## 5. 视图与界面

- 俯视图：每种形体画它的真实轮廓（圆 / 多边形 / 拱的两腿 / 环），悬空的画虚线 + 高度标，桥画跨越线，屋顶用不同的纹样；按 plan_id 高亮整组。
- 3D：每种形体用对应的 three.js 几何（Box / Cylinder / Cone / Sphere 半球 / Torus / 拉伸多边形），悬空岩块用倒锥；水面半透明；桥、台阶有实体。
- 剖面：带内形体按真实高度画轮廓（锥、穹顶画成三角 / 半圆）。
- 右栏「构成」= **场景树**：地形操作一组，节点按树展开（组 → 子节点，repeat 显示「× 6 · 环形」），每项旋钮从 schema 生成（尺寸、数量、半径、间距、偏移、旋转、离地、屋顶、标签）；「＋」可加形体 / 组 / 重复 / 连接 / 生成器 / 地形操作；拖图上的东西 = 改它的 `offset_m`（在父组坐标里反算）或 `at`。
- 三张卡 = 三个概念：卡片上写概念一句话 + 关键结构，缩略图是编译后的俯视图。

## 6. 验收

- 用 DeepSeek 跑「我要生成魔法学院」「赛博朋克夜市一角」「海盗港口」「沙漠里的古神殿」「空中花园」「山城村庄」：每句三张卡的**空间组织方式**明显不同；除「山城村庄」外不应出现台地 + 撒房子的老三样；画面上能认出关键结构（塔群、院落、浮岛、码头、神殿轴线 …）。
- 编译确定、validate 无 error、600 形体内编译 < 500 ms；本地操作 0 次 AI；测试全部通过。

## 7. 第 1 轮验收后的决定（2026-10-19）

- **角色词不是形体**：神殿 / 城堡 / 书库 / 广场 / 祭坛说的是「这个地方的主体是什么」。程序的名字、概念、关键结构里说到了就算有；都没说到，给现有地标改个名；只有连地标都没有才补。不再往每张卡塞同一个 30×16×22 的四坡顶盒子。
- **「空中」按这张自己的组织满足**：已有悬空的组 / 平台 / 浮岛就算；没有时把主体所在的组整体抬起（锚在坑底的先抬出坑口），出生点补一段登空石阶。不再给三张都加同一组「4 座浮岛 + 光桥」。构思提示写明：说死的词三个概念都要满足，只是方式不同。
- **补位不套预设**（desktop/providers.py `recipe_from_concept`）：terrain_idea 落成抬起 / 坑 / 环 / 湖 / 峡谷；key_structures 逐条出形体，按词挑排法（环 / 夹道 / 一排 / 悬浮 / 散布），从主体外沿一圈圈往外排；只有说到具体结构（金字塔、码头、迷宫…）才借片段；「云海」不再被当成海。两张补位卡的结构钥匙相同 → `diversity.clones` + 警告。
- **看得见模型错在哪**：回喂前那一轮的 schema 错进 `_steps[k].first_errors`，评测报告落盘。提示词写清锚点只能是 `id` 或 `id.部位`（组里的子节点直接写自己的 id，本地也把 `组.子` 修成 `子`），以及 `linear` 默认沿 x、`mirror axis:x` 是左右翻、夹道的写法。沙漠神殿真调用一次过 3/3（4 次 HTTP，¥0.043）。
- **引擎**：实例重合检查（镜像轴写反）+ 修法；主地标取节点自己的体块；连接走不通只画两端 + 虚线（`unrouted`，不算可走）；出生点避开水面；3D 地面按 site.ground / 色板的地面色上色，`ground: sky` 只画一层半透明云。

## 8. 第 2 轮验收后的决定（2026-10-19）

- **elev_m 一个意思：离地**。形体的子节点写了 `elev_m` = 离父体**底面**的高度（就是立面上的高度），低于父体顶就挂在立面上（`land: rest, from: "base"`）——外挂平台、挂壁摊架、招牌、阳台；≥ 父体高就在屋顶以上；不写 `elev_m` 的子节点照旧立在父体顶上；浮岛的子节点从岛面量（岛面是它们的地面）；锚 `X.top` 的照旧从 X 顶面量。挂立面的子形体中心还在父体里面时，引擎沿它的偏移方向把它推到外墙外（搭进去 ≤ 0.5 m），记 `facts.plan.autofix`（attach）。偏移为 0 的（套在管子上的阀盘、塔身外的环）不动。
- **避让不再把悬空的关键结构推走**：两块悬空的竖向只叠一点（< 1 m 或 < 薄的那块一半）、或贴地那块的顶只顶到悬空那块的底部 = 搭在上面，不算撞（雨棚压在钢架和广告柱顶上）；推的距离按推的方向量半个自己（34 × 150 的雨棚往东西最多 17 m），重复按单个实例的尺寸量；悬空的形体推完中心不能离开它锚着的东西（雨棚得还在街上），推不了只报告。环（torus / 空心圆柱）套住的东西（同心、或整个在内孔里）不算撞；两个圆形底面按圆算。
- **镜像模板在翻转轴上直接修**（真卡里最常见的错）：重复自己写了沿翻转方向的偏移 → 当成对称半间距挪给模板；模板只在另一个方向偏 → 换轴；单个形体 → 偏开半个宽 + 1 m。都记 `facts.plan.autofix`（mirror），提示词加了一行「偏移写在 child 上」的片段。
- **台阶不换形体**：`stairs` 的 `shape` 不再把它画成大圆柱；写圆的（cylinder 等）= 螺旋梯：中柱 + 每级 30° 绕柱升起的踏步（直径 = size_m[0]，高 = size_m[1]）。
- **崖外不垫高柱**：贴地形体要垫的基座比它自己高两倍以上时，往锚点 / 重复中心收（每次 2 m），收到站得住为止（autofix pull_in）；收不回来就不垫，悬在边上并警告（空心的竖井筒壁照旧垫到底）。
- **出卡调用上限**：`/api/ai/draft` 收 `max_calls`（1–8，默认 8），一次出卡最坏 8 次 HTTP，超了那张由模拟 AI 补位。
- **补位的「长堤 / 堤道 / 中轴甬道」= 一条长台面**，主体立在它中段，两侧对称的楼落在堤外；不再把堤当成一栋 32 × 18 × 24 的楼。

## 10. v5f 第 1 轮验收后的决定（2026-10-19）

- **线形地形的方位锚点 = 岸**：沟 / 河 / 坡道（`r.line`）的 `.N / .SW / …` 取线的法向里和该方位同侧的那一边，在线的中段离中线「半宽 + 边坡宽 + 1.5 m」；新增 `.left / .right`（顺着 from → to 走的左 / 右岸）。方位和线差不多平行时照旧取那一头。两岸对望 = 一组锚 `trench.left`、一组锚 `trench.right`，桥 `from: trench.left, to: trench.right`。台阶边的沟每级宽 2 × 级高（2–6 m）。锚在 `<线>.mid / .start / .end` 的 rect / ellipse 地形操作不写 `rotate_deg` 时长边顺着线（layout.js `lineBank` / `alongDeg`）。两端相距 < 3 m 的连接进 `links_routed`（「锚点重合」+ 修法：写成两岸 / 连到两个不同的东西）。
- **高架组的 elev_m 只抬台面**：组离地 > 2.5 m 时，组里没写 elev_m 的柱 / 方 / 圆柱 / 棱柱（重复看模板）高在 0.7–1.25 × 离地高之间的 = 墩，落地并从脚下撑到台面底（`autofix: support`）；写了 `ground: "snap"` 的子节点也落地。没落地、又高到戳出台面的竖向件（拱、墙、墩）进新检查 `supports_grounded`「支撑悬空」，修法 `ground: "snap"`。提示词写明：高架 / 天桥只给桥面写 elev_m，墩、柱、拱写在组外或加 `ground:"snap"`。
- **模拟配方不再是三分法**：每个题材 4–6 个组织（学院：塔环 / 水网 / 中轴 / 浮空 / 环廊 / 地宫），按 variant 轮换取三个，一批里最多一个「往上」（`dir: up`：塔 / 崖 / 浮空）、最多一个「往下」（`dir: down`）。新加的配方只写概念（`auto`），由 `recipe_from_concept` 按词搭；`?demo=cards` 现在是「塔环学院 / 水网书院 / 中轴书院」。锁定的数量词（七座法师塔）在只有一座同类（钟楼）的卡上补一组同名的。
- **「地下」标签收紧**：压低 > 6 m 只有崖 / 台阶边、或深 ≥ 短边 15% 才算地下 / 下沉；宽而缓的谷（160 × 100 深 8）算峡谷 / 盆地。
- **环孔里的东西**：方块四角伸进环带时，重叠报「伸进环带 X m：缩到内径 D m 以内」，修法按比例缩它的 size_m（不再报「推了半个尺寸还差 48 m」）。
- 视图：第一眼里近处的环墙少混雾（≤ 0.25），灰墙撞灰天时压暗，加上沿描边和竖向分格；俯视图同心的几圈环只标最外一圈，孔里的东西标在它自己中间，前缀去重按根组算（「柱厅」标过了，组里的「柱」不再标），标签之间留缝。

## 11. v5f 第 2 轮验收后的决定（2026-10-19）

- **视角从 3 个减到 2 个，至少一个概念不用视角**：上一轮三张卡几乎 1:1 照抄抽到的三个视角（why_different 直接写「设计动机来自水网」），22 个视角成了更大的一套预设。现在每次只抽 2 个，系统提示和用户消息都写「至少一个概念不用视角，只从题材的灵魂结构出发」；why_different 用题材自己的话说动机，不引用视角名。
- **括号少一截不再把根上的东西吞进 nodes[0]**：JSON 修复把缺的闭括号补在末尾时，spawn / relations / palette / lighting / mood / site / terrain 会落进某个节点、后面的根节点成了它的 children（真卡「悬台叠翠」：没有出生点、没有关系，7 个根节点成了地标组的子节点）。`ai.fix_misnested_root` 在后处理第一步把这些键挪回根上，children 里从第一个锚到组外（site.* / 地形操作 / 别的根节点 / 组自己）的那个起整串插回它所在根节点后面（至少留一个子节点）。
- **组织标签按尺度称重**：压低 > 6 m 的坑里放了东西才是「地下」3，只有悬在坑上方的（浮圃 / 环桥）算 1、空坑算 2；< 3 m 的 carve 不算、窄于 8 m 的沟是细节；水面 ≥ 场地 4% 或长过场地短边一半才算「水上」；墙要围住场地短边一半以上、院子 ≥ 短边 30% 才算「围合」（广告墙 / 井口护栏是细节）；几块高低不同的叠台（塌落的楼板）算「台地」2；新标签「网格」= 网格重复（模板不是细节）或三条以上的渠 / 沟（水网）。
- **高架组里的拱 / 门 / 柱自动处理**：组离地 > 2.5 m、没写 at / elev_m / ground 的拱、门、柱（或一排）戳出台面时：组里有台面（扁平的 platform / box / cylinder）且它矮于 0.6 × 离地高 → 立到台面顶上；高的 → 落地并撑到台面底；组里没有台面（真卡「天门花道」elev_m 24 的仪仗组只有三座门拱）→ 落回地面。都记 `autofix: support`；墙 / 方块之类还进 `supports_grounded` 检查。
