# 05 · AI 原生的场景构成（v4）

> 2026-10-19，用户试用 v3 后的三句话：
> 1. 「怎么只有纵深啊」「我说生成迷宫，迷宫呢」——「矿洞是个迷宫」最后只是一根更深的长方体。
> 2. 「这些都是预设的吗？是的话，不够 native」——右栏参数是 3 种原型、5 种地标、4 个位置、3 档坡度的菜单。
> 3. 「你代码写的像微服务一样」——前端 20 多个小模块靠 `initX(deps)` 互相注入，后端 7 个 ai_* 模块套娃。
>
> 本文是 v4 的唯一规格，替代 docs/03 的 Card 与 docs/04 的「参数面板」。docs/03 的六原则仍然成立，只改一条（见第 1 节）。

## 1. 原则的变化

| 原来 | 现在 |
| --- | --- |
| LLM 永远不写坐标 → 只能从枚举里挑（原型 / 地标种类 / 放置类） | **LLM 仍然不写坐标**，但可以**自由组合**：任意数量的地形块、区域、建筑类型、地标、路、地下 / 空中空间、房间；名字随便起（「吊脚木楼」「风雨桥」「戏台」「矿洞迷宫」）；尺寸用米；位置用**相对关系**（在谁的顶上 / 边上 / 尽头 / 下面、朝哪个方向、离多远的比例） |
| 引擎 = 按原型生成 | 引擎 = **编译器 + 求解器**：把构成图解析成几何，相对关系解成坐标，检查关系是否成立 |
| 3 种原型是菜单 | 3 种原型变成**示例构成**（写在提示词里给 AI 参考，也给模拟 AI 用），不是选项 |
| 右栏是固定的参数菜单 | 右栏是**这次生成出来的构成清单**：AI 生成了什么就列什么，每一项有它自己的旋钮（数字 → 滑块 / 步进，枚举 → 分段，名字 → 可改文字，关系目标 → 下拉选其它元素）；可以「＋」加一项、删一项，全部本地 |
| 空间只有外轮廓 + 深度 | 空间有**内部布局**：迷宫、矿道、厅堂、洞穴网、单室、地道，或**直接给房间清单和连接**（「前厅—甬道—主墓室，两侧耳室」），引擎排平面 |

不变：说 → 选 → 改 → 出；只有打字 / 重出 / 换一批调 AI；本地操作可撤销；说死的条件本地锁定；导出 SID + BRIEF + PROTOCOL。

## 2. 构成图（plan）——AI 的输出

### 2.1 词表（开放的地方与收紧的地方）

- **名字（label）完全开放**。`id` 是 AI 起的英文小写短名，供引用。
- `terrain[].type`：`hill`（穹顶山）、`ridge`（长条山脊）、`slope_terraces`（坡上一层层叠的台地带，带 `steps`、`orient` 上坡方向）、`ring_terraces`（围着中心一圈圈的台地）、`plateau`（平台）、`cliff`（陡崖边）、`valley`（谷，负）、`basin`（盆地，负）、`pit`（坑）、`island`（四周低的高台）。这是几何原语，不是场景模板；数量和组合不限。
- `buildings[].form`：`house`、`stilt_house`（吊脚楼：可以站在坡上，不要求平地）、`courtyard`（院落）、`round_house`（土楼式圆楼）、`tower`、`hall`、`pavilion`、`gate`、`bridge`、`stage`、`wall`、`well`、`tree`、`statue`、`custom`（按 size 的盒子）。form 决定引擎怎么生成体块（屋顶 / 柱脚 / 圆形），**label 才是给人看和给引擎侧的名字**。
- `zones[].use`：`housing`、`market`、`plaza`、`farm`、`terrace_farm`、`forest`、`temple`、`dock`、`yard`、`ruins`、`other`；`on` 引用地形块 / 空间；`levels`：`"all"`、`"low"`、`"mid"`、`"high"` 或层号数组；`side`：方向，可选。
- `place.rel`：`top_of`、`center_of`、`edge_of`、`end_of`（路 / 长条的尽头）、`beside`、`behind`（相对 spawn）、`between`（`target` 为两个 id）、`under`、`above`（目标是地标时立在它身上：桥 → 桥面，其它 → 顶面，和它不算重叠，如桥心楼阁在风雨桥上）、`along`（沿路）、`at_entry`；可选 `side`（方向）、`facing`（`spawn` / id / 方向）、`gap_m`。模型写了枚举外的近义词（`across` / `on` / `near` …）时本地先换成枚举里的，记进 `_fixes`，不回喂。
- `at`：`{ of: "site" | id, dir: "C|N|NE|E|SE|S|SW|W|NW", dist: 0–1 }`——相对位置的比例，不是坐标。
- `spaces[].layout`：`chamber`、`corridor`、`maze`、`galleries`（矿道：主巷 + 横巷 + 采场）、`halls`（中轴对称厅堂）、`network`（洞穴网）、`rooms`（按 `rooms` + `links` 排平面；`"entry"` 是保留节点，表示从地面下来的入口）。空中空间用 `chamber` / `corridor` / `network`（平台用栈道 / 索桥串起来）/ `rooms`。
- 数值：尺寸用米（有范围，越界夹回），层数是小整数，density 0–1.6，`branching`：`low|medium|high`，`sublevels` 1–3。

### 2.2 硬约束（JSON Schema 校验 + 本地夹取）

- 不允许出现 `position` / `x` / `z` / `points` 这类坐标字段（schema 层面就没有）。
- 引用必须指向已存在的 id（不存在的引用：本地降级到 `site` 并在聊天里提一句）。
- 用户那句话里说死的条件（时段、溪、地标名、层数、坡度、入口方向、迷宫 / 矿洞 / 地宫 / 栈道 …）本地锁定：三张都要有。

## 3. 编译（engine/plan.js）

`compilePlan(plan, { seed }) → sid`（SID 结构不变：terrain.features / regions / volumes / paths / markers / spaces / relations / meta），再走现有的 `resolve` 布房、算主路、算关系。步骤：

1. **场地**：bounds = ±size_m/2；layer_m。
2. **地形块**按顺序解析 `at` → 中心点（of 的中心 + dir 单位向量 × dist × of 的半径），按 type 生成 plateau 多边形 / 穹顶特征（复用 terrain.js 的 featureContribution 叠加规则：正特征取最大、负特征相加）：
   - `slope_terraces`：在 size 矩形里沿 `orient`（上坡方向，默认背离 spawn 一侧）叠 `steps` 条台地带，层号 from_layer…；
   - `ring_terraces`：以中心为圆心叠环，内高外低（或 `inverse: true` 内低外高）；
   - `hill` / `ridge`：穹顶 / 拉长穹顶，顶高 top_layer；`plateau`：圆角多边形，平台高 layer；`cliff`：skirt 极小的台地边；`valley` / `basin` / `pit`：负特征；`island`：高台 + 四周负特征。
   - 每块记 `plan_id`，台地 feature id = `<plan_id>_<k>`。
3. **区域**：`on` 地形块的台地多边形，按 `levels` / `side` 选子集，生成 regions（带 `plan_id`、use、density、building）。
4. **建筑类型**：layout.js 布房时按 region 的 building 取尺寸与 form；`stilt_house` 允许跨坡（柱脚高 = 坡下地面差，体块底面取上坡角高度）；`courtyard` 一次放一组（围合 4 栋）；`round_house` 用圆柱。
5. **地标**：`place` 求解——按 rel 求候选点集（top_of = 目标最高平台内点；edge_of = 目标边界上朝 side / 朝 spawn 的点；end_of = 路或长条末端；center_of = 质心；beside / behind / between / along / at_entry 同理），按「不压路、不压房、关系检查更多成立」挑第一名（确定性）。
6. **spawn**：同 place 求解；`look_at` 决定朝向。若 relations 有 `visible_from(x, spawn)` 且看不见，沿候选点集换下一个点。
7. **路**：节点 → 坐标（spawn / 地标 / 区域质心 / 地形块顶），按 style 选路由（winding / stairs → A*；zigzag → 之字；straight → 直线检查坡度；bridge → 跨谷直线 + 桥；tunnel → 走地下）。第一条路是主路 `main_trail`。
8. **水**：stream 沿谷线 / from→to 路由。
9. **空间**：位置 = `under` / `over` 目标的投影；深度 = depth_layers；**内部布局**见第 4 节；连接点在 `connect.from` 目标附近。
10. **关系**：plan.relations 全部进入检查（成立 / 不成立 + 修法）。

确定性：同一 plan + seed → 同一 SID。每个生成物带 `plan_id`，界面靠它把图上的东西和构成清单对应起来。

## 4. 空间内部布局（engine/interior.js）

同 docs/04 §8，并加 `rooms` 布局：
- `maze`：外轮廓（size_m 方形，夹在地形下 ≥ 2 m 岩层）内铺网格（格 = corridor_m × 2），种子化深度优先生成树；branching 决定打通的死路比例（low 0%、medium 15%、high 35%）；入口格靠近连接点，**终点室**放在 BFS 最远的格；每个 sublevel 一张迷宫，层间连接放在两层都可达的格。输出 passages（合并共线段的折线，带宽）+ rooms（入口室 / 终点室 / 小室）+ links。
- `galleries`（矿道）：主巷沿长轴，两侧每 8–10 m 一条横巷，部分尽头是采场；多层时每层一套，层间暗井在主巷端部。
- `halls`：前厅 → 甬道 → 主厅 → 后室，两侧对称耳室。
- `network`：3–9 个不规则洞室，最小生成树连弯曲通道，再加 0–3 条回环。
- `rooms`：把 rooms + links 图排到网格上（BFS 分层 + 冲突时换格，确定性），房间按 size s/m/l = 6/10/16 m，连线变成走廊。
- 事实：通道总长、房间数、死路数、回环数、入口到终点最长路线（米）。检查：`interior_connected`（全部可达）、净空（每层每条通道都在地面下 ≥ 2 m）。

## 5. AI 改动（revise）——plan patch

```json
{ "understood": true, "restatement": "矿洞改成两层的迷宫，岔路多。",
  "ops": [ { "op": "set", "id": "mine", "field": "layout", "value": "maze" },
           { "op": "set", "id": "mine", "field": "branching", "value": "high" },
           { "op": "add", "group": "landmarks", "value": { "id": "stage", "label": "戏台", "form": "stage", "size_m": [10, 6, 8], "place": { "rel": "edge_of", "target": "plaza", "side": "N" } } },
           { "op": "remove", "id": "cliff_e" } ],
  "question": null, "ask_to_point": false }
```
- `op` ∈ `set | add | remove`；`set` 的 field 只能是该元素 schema 里的字段（包括嵌套如 `place.rel`）；`add` 的 value 必须通过该组 schema；`remove` 时引用它的东西本地降级。
- 本地锁定：revise 的那句话里说死的词也锁（「迷宫」→ 相关空间 layout = maze；「三层」→ sublevels 3 …）。

## 6. 界面（「改」）

- 右栏第一块是**构成清单**，按组折叠：地形 / 区域 / 建筑 / 地标 / 路 / 空间 / 关系 / 外观。每项一行：名字（可点改）+ 关键值（「环台 · 5 级 · 从 1 层起」）；点开是这一项的旋钮（从 schema 生成：数字 → 步进 + 拖动，枚举 → 分段，引用 → 下拉）；每组底部「＋ 加一个」（按 type 的默认值生成，可改名）；每项「删除」「锁」（锁住的项换一批时不动）。
- 点清单里的一项 = 在图上高亮它生成的所有东西（按 plan_id）；点图上的东西 = 清单里展开对应的项。
- 图上拖动：地标 / spawn 拖动 → 写 `place.nudge_m: [dx, dz]`（人给的微调，AI 看不到坐标，只看到「人挪过」）；地形块拖动 → 改 `at.dir` / `at.dist`（反算成方向与比例）；空间拖动 → 改 `offset_m`；房子拖动同 v3（锁住的单栋）。
- 空间选中后：布局分段、大小、岔路、内部层数、走廊宽、「换一个」；地下层俯视图画出通道 / 房间 / 入口 / 终点，内部层可切。
- 原来的固定参数面板删掉；时段 / 色板放进「外观」组。
