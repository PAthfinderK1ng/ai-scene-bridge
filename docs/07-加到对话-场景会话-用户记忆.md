# 07 · 加到对话、场景会话、用户记忆、随意调高度（v6）

> 2026-10-19，用户：圈了一块（2950 m²，约 81×48 m），弹出「树林 / 田 / 撒房子 / 水池 / 平台 / 算了」；接着打字「还是没改」，AI 回「你只说『还是没改』，没指出要动哪一处」。
> 用户要：**把东西都添加到对话**；**不同场景不同会话**；**用户记忆模块**。

## 0. 查到的原因

| 现象 | 原因（代码） |
| --- | --- |
| AI 不知道圈的那一块 | `app.js` 的 revise 只发 `{ plan, action: { type: "text", text } }`，圈选、选中、画的线都不进请求 |
| 「还是没改」听不懂 | revise 不带对话历史，也不带「上一轮改了什么 / 有没有生效」 |
| 圈完弹固定菜单 | `GEN_CHOICES` = 树林 / 田 / 撒房子 / 水池 / 平台——又是预设 |
| 改了但看不出变化 | 没有「改动前后对比」的反馈，ops 被锁 / 被丢 / 改了不显眼时人不知道 |

## 1. 加到对话（引用）

**任何东西都可以加到对话**，像在编辑器里把代码选区加进聊天：
- 图上点选的节点 / 重复里的一个实例 / 地形操作 / 连接 / 空间 / 出生点；
- **圈的一块**（圈区域工具）、**画的一笔**（画路工具）、**点的一个位置**（图钉：右键或 Ctrl+点击地面）；
- 剖面上点的东西；场景树里的一项（每行「加到对话」按钮，或拖进输入框）；
- 输入框里打 `@` 弹出节点名补全。

加进去的东西在输入框上方显示成**引用卡片**（名字 + 一句事实，例：「📍 圈选 1 · 81×48 m · 地面 +3–7 m · 含 主宅、谷仓」），可单个移除；发送时一起进请求，发完清空（可钉住保留）。

### 1.1 人画的几何 = 标记（marks）

圈的一块 / 画的一笔 / 点的位置是**人给的几何**，存进程序的顶层 `marks[]`（不是建筑，只是参考）：
```json
"marks": [
  { "id": "mark_1", "type": "area",  "label": "圈选 1", "polygon_m": [[x,z],…] },   // 相对场地中心，x 东 z 南，米
  { "id": "mark_2", "type": "trace", "label": "手绘线 1", "path_m": [[x,z],…] },
  { "id": "mark_3", "type": "pin",   "label": "图钉 1", "point_m": [x,z] }
]
```
- 坐标是**人**写的，AI 不写；AI 用它们当锚点：`at: "mark_1"`（area 的中心）、`area: "mark_1"`（散布 / 生成器范围）、`along: "mark_2"`（沿线重复 / 连接）、`at: "mark_3"`。引擎（program.js）解析这些锚点。
- 俯视图把 marks 画成虚线轮廓 / 虚线 / 图钉，可拖、可删、可改名；不参与碰撞、不进导出几何（导出时写进 SID meta 供参考）。
- 圈区域的弹窗改成：**「已加到对话，说说这块要做成什么」**（输入框自动聚焦，占位「这块要做成什么？」）+ 本地快捷「清空这块里的东西」「算了」。**不再给固定菜单。**

### 1.2 引用进请求

revise 请求多两样：
```json
{ "plan": …, "action": { "type": "text", "text": "这里做成夜市" },
  "refs": [ { "kind": "mark", "id": "mark_1", "label": "圈选 1", "facts": { "size_m": [81,48], "area_m2": 2950, "ground_y": [3,7], "contains": ["main_house","barn"], "near": ["gate"] } },
            { "kind": "node", "id": "towers", "instance": 2, "label": "法师塔[2]", "facts": { "type": "tower", "size_m": [8,34], "at": "rock.top" } } ],
  "history": [ { "role": "user", "text": "把谷仓弧墙连起来" }, { "role": "ai", "text": "…", "ops": 2, "effect": "谷仓弧墙：新增 1 段墙；没有看得见的变化：0" } ] }
```
- 提示词：「这 / 这里 / 这块 / 它」优先指 refs；「还是没改 / 再来 / 还不够」看 history 的上一轮：上一轮改了什么、effect 怎么说（没生效就换种改法，生效了就加大力度）。
- `effect`：前端每次应用 ops 后算一份**改动摘要**（engine `diffCompiled(before, after)`：新增 / 删除 / 挪动 / 变大变小的节点，最大位移、包围盒变化；若几乎没有看得见的变化，写「没有看得见的变化」），显示在聊天里（「改了：法师塔 ×6 → ×8，半径 33 → 40 m」），也写进 history。

## 2. 场景会话

- 左上角**场景列表**（可收起的侧栏）：每个场景 = 名字、缩略图、最后修改时间；「＋ 新场景」「重命名」「复制」「删除」（删除要确认，进回收站 7 天）。
- 每个场景保存：程序（plan + seed）、三张候选（concepts + plans）、聊天记录（含引用卡片与改动摘要）、撤销栈（最近 30 步）、视图状态（图层、剖切、3D 小窗）。
- 存储：本地服务 `/api/scenes`（`GET` 列表、`POST` 新建、`GET/PUT/DELETE /api/scenes/<id>`），文件在 `%LOCALAPPDATA%\ai-scene-bridge\scenes\<id>.json`；前端改动后 1.5 s 防抖自动保存；启动时打开上次的场景；离线 / 服务不可用时退回 localStorage 并提示。
- AI 请求只带**当前场景**的历史（最近 10 轮，长的压成一句）。

## 3. 用户记忆

跨场景的偏好，让 AI 记住「你是谁、喜欢什么、讨厌什么」。
- 记忆条目：`{ id, text, kind: "like"|"dislike"|"rule"|"fact", scope: "global"|"scene", scene_id?, source: "you"|"ai", enabled, created, uses }`。
- 来源：
  1. **你说的**：「记住：……」「以后都……」「我不喜欢……」——本地识别成记忆，直接保存并在聊天里回「记住了：……」；
  2. **AI 建议的**：draft / revise 的输出多一个可选字段 `memory_suggestions: [{text, kind}]`（模型发现你表达了长期偏好时才给，**不额外调用**），前端显示「要记住吗：夜景优先 [记住] [不用]」；
  3. 每条聊天消息旁「记住这个」。
- 使用：所有 AI 调用（构思 / 展开 / 改动）的系统提示后附「用户偏好（跨场景）」，按 kind 分组、最多 20 条、只放启用的；场景级记忆只在本场景用。用了哪几条记在 `_usage.memory_ids`，聊天底部那行写「用了 2 条偏好」。
- 记忆面板（顶栏「记忆」）：列表、开关、编辑、删除、来源与使用次数；「清空」要确认。
- 存储：`/api/memory`（GET 列表、POST 新增、PUT/DELETE 单条），文件 `%LOCALAPPDATA%\ai-scene-bridge\memory.json`。
- 本地锁定照旧，记忆是「偏好」不是「硬条件」：提示词里写明「这句话说的优先于偏好」。

## 4. 随意选点调高度（用户补充：「图上随意选点调整高度的功能也没实现」）

v3 能在剖面上拖台地，v5 换成地形雕刻后剖面只剩一条地面线，**哪儿都拖不了**。现在：
- **俯视图「高度」工具**（快捷键 H）：在地面任意一点按下，上下拖动 = 抬高 / 压低（拖动时显示「+4.5 m」并且 3D 小窗实时变）；滚轮或 `[` `]` 调笔刷半径（默认 12 m，显示圆圈）；按住 Shift = 削平到按下点的高度；按住 Alt = 只压低。松手生成一个**人给的地形操作**：先在那儿放一个图钉标记（marks 里的 pin），再加 `{ op: "raise" | "lower" | "flatten", at: "<pin id>", shape: "circle", size_m: [半径×2, 半径×2], height_m | depth_m, edge: "slope" }`。同一个图钉上连续拖 = 改同一个操作，不堆新的。
- **剖面**：地面线上任意一点都能抓（悬停时出现把手和当前高度），上下拖 = 在剖切线上那个位置做同样的操作（用剖切路径把距离 d 换成俯视坐标）；选中的地形操作在剖面上显示它的高度把手，拖它改 height_m / depth_m。
- **已有的地形操作**：选中后俯视图上显示中心把手（拖 = 挪位置，改 offset）和高度把手（上下拖 = 改高度）；场景树里同样有旋钮。
- 这些都是本地操作，进撤销栈，不调 AI；AI 下次请求时能在程序里看到这些人加的操作（label 写「手调高度 1」），可以引用。
- 引擎：地形操作的 `at` 支持 marks；`flatten` 支持 `target: "at_point"`（削到图钉处原来的高度）；平滑边（edge slope）按半径的 40% 过渡。

## 5. 验收

- 圈一块 → 输入「这里做成夜市」→ AI 在 mark_1 里放了夜市（锚到 mark_1），图上看得见；再说「还是太空了」→ AI 看 history，在同一块里加密度 / 加东西，摘要写清改了什么。
- 选中「法师塔」→ 加到对话 →「再高一点」→ 只改它；`@主殿 换成穹顶` 生效。
- 新建场景 B，A 的聊天不出现在 B；切回 A 一切还在；重启应用后都在。
- 说「记住：我喜欢夜景，不要撒小房子」→ 记忆里两条；新场景出卡时三张都是夜里、都没有撒房子；记忆面板能关掉它们，关掉后不再生效。
- 高度工具：在俯视图任意一点拖 +5 m，剖面与 3D 跟着变；剖面地面线任意一点拖；撤销能回去；AI 下一轮能看到「手调高度 1」。
- 本地操作 0 次 AI；新增功能不额外调 AI（记忆建议跟着原有调用回来）；测试全部通过。

## 6. 验收后修正（第 2 轮）

- **同一点连拖**：松手后选中的手调操作的中心把手正好压在图钉上，第二次按下点中的是把手——现在把手 = 图钉：按在图钉、按在选中手调操作的中心把手、或离已有手调图钉 ≤ 2 m，都接着改同一个操作（+4 再 +4 = +8），不堆新的。
- **Shift = 纯削平**：削到按下点原来的高度，竖拖不再叠加偏移（要削平后再抬，松手后拖高度把手）。
- **「还是太空了」只落在那一块**：这句没加引用、又是接着说的（还是 / 再 / 更 / 这里…），前端把上一轮的引用带上（`carried: true`，事实重新算）；history 里人那条带 `refs`、AI 那条带 `ids`（动了的 id）；提示词：只动上一轮动过的、人指的那块和锚在它上面的，别处不顺手改；加个数要缩间距，个数 × 间距仍放得下。
- **引擎兜底**：锚在圈选里的直线 / 网格 / 放射重复排不下 → 缩间距 / 半径（缩到挨着还放不下就少放几个），记进 autofix；避让时撞上的是自己子孙里的一小件或自己的环带，最多按那一件 / 带宽推，同心环廊不被推散（推不开就报告重叠）。
- **改动摘要**：没改定义、被别人挤走的节点单列最前面「顺带被挤动：…」，不藏进「等 N 处」。
- **用量行**：只数真调了模型的展开（「展开 ×0（3 张模拟补位）」）。
- **夜景 3D**：夜里灯 / 灯笼 / 火这些小件自己发光（细高灯柱顶上点一盏）。
- **测试不碰真实数据**：`/api/health` 带 `data_dir_custom`（只说换没换数据目录，不给路径）；flow.test 在没换数据目录的服务上直接拒绝。

## 7. 俯视图按层显示（2026-10-20，用户：「不应该这么分 应该按层分 第一层初始就是0 往上1 往下-1」「用户自主添加」「点到一层单独显示 或者 穿透高亮显示 但是可以自己选多少层进行穿透」）

**层的口径（与 tools/score_readback.py 同一套）**：层不是 `layer_height_m` 的 3 m 切片，而是场景里实际的台地 / 平面。引擎 `terrain.js findLayers`：基准面 ∪ 旧式多边形特征质心处的实际高度 ∪ 高度场里四邻同高的平坦面（≥ 10 格 ≈ 40 m²），0.35 m 内合并；出生点所在层为 0、往上 +1、往下 −1（`T.layers / T.layerTable / T.zero / T.layerAt(x, z) / T.layerNo(h)`）。点、房、树、路段按脚下地面的高度归到最近的层。旧的 `T.levelAt`（切片）只给布房 / 支路 / 等高线用。

**存进文档**：`sid.terrain.layers[]`（`{id, height_m, label?, source: auto|user, no}`）与 `sid.meta.layer_zero`（0 层高度）/ `layer_zero_from`（spawn / user / base），`resolve` 每次写；评分脚本读到 `terrain.layers` 就直接用它，不再自己找平面（`meta.layer_zero` 定 0 层）。人定的层表放在 `plan.site.layers[]`（`{height_m, label?}`）与 `plan.site.layer_zero_m`：写了就以它为准（引擎不再自动加层），删掉就回到自动；导出的 SID 的 `meta.plan` 带着它，重编译还在。

**界面**：俯视图左侧「地面」下面一列层按钮（高的在上）：全部 / +N … 0 … −N / 单层 · 穿透 / 穿透 ±1 · ±2 · 全部 / 层…。单层 = 只画这一层：面状的（地形、区域、路、水、等高线）按这一层的地面范围裁剪（1 m 采样的 clipPath），点状的（房 / 树 / 地标 / 出生点）与标签按归属层显隐；穿透 = 当前层实画，其它层用 `<use>` 按各自范围复制、按层差淡显（1 层 0.45、2 层 0.28、3 层 0.17、再远 0.12），不接指针。右栏「场地」里有层表：每层一行（层号、高度、名字、设为 0、×）、＋加一层（填高度）、恢复自动；点图上一点的选中卡有「以这里的高度加一层」。剖面的层线 / 台地标题 / 「爬升（a→b 层）」、导出页脚与 BRIEF 都按同一口径标 0 / +1 / −1。3D 预览本来没有层号标注，没改。天上 / 地下仍是原来的大类按钮（用户 10-20 选定：大类照旧，地面下面出层按钮）。

**测试**：`medium/engine/tests/layers.test.html`（层表 / 云岭寨 0 … 4 层与竹林 −1 / 人定层表与 0 层 / findLayers / 按层渲染），`tools/test_score_readback.py` 加 3 条（SID 自带层表）。
