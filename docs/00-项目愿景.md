# 00 · 项目愿景

> 记录立项时的原始想法，作为后续调研与设计的基准。日期：2026-10-17

## 想做什么

探索「AI 制作游戏」（Unreal Engine 与 Unity）。
目前 AI 写游戏逻辑已经可用，但在**设计地图 / 搭建关卡场景**上有明显短板。
我想做一个**中间层**小工具，让用户和 AI 高效交流三维场景：

- 用户在工具里直接操作三维空间：摆放体块、画区域、标注语义（这是山 / 路 / 出生点）、取色或贴参考图；
- 工具导出 AI 能读懂的文件或文字（结构化场景描述 + 必要的视觉参考）；
- AI（Claude Code / Cursor + 引擎 MCP 或脚本）读取后，在 UE / Unity 中把场景落地。

## 观察到的四个痛点

1. **AI 写地图都是代码。** 它用程序化脚本和硬编码坐标生成场景，推测是三维空间理解能力不行。
2. **想象与现实有出入。** 用户脑中的场景和 AI 搭出来的不一样，根因是自然语言不能充分描述三维空间（位置、尺度、朝向、层次、遮挡、视线）。
3. **上色问题。** AI 不知道你具体想要什么颜色 / 材质 / 风格，即使告诉它「这是山、这是树」。
4. **搭不出具体的样子。** AI 不知道怎么搭出「长成那样」的场景，只能用简单几何体堆叠，这很大程度限制了 AI 制作游戏。

## 要回答的问题

1. 这四个痛点是否真实、普遍？哪个最痛？哪个已经被现有工具解决，或会被模型进步自然消解？
2. 「中间层 3D 工具」这条路可不可行？
   - 导出什么格式 AI 最容易读懂并复现？（几何 / 语义 / 截图 / 调色板 的组合）
   - 直接在引擎里 blockout 再让 MCP 读取，是否已经足够？独立工具的价值在哪？
   - 与 UE / Unity 的对接路径与工程量？
   - 一个人 1–2 个月能做出什么样的 MVP？
3. 现在谁已经在做类似的事？（学术中间表示路线、引擎内置 AI、MCP 工具、3D 资产生成、世界模型、场景级 AI 工具）我们的差异化在哪？

## 成功标准（初版）

- **调研阶段**：对四个痛点各给出「成立 / 部分成立 / 不成立」的判定与证据；对方案给出「可行 / 有条件可行 / 不可行」的判定与前提。
- **验证实验**：同一个目标场景，分别用「纯文字描述」和「中间层导出」交给同一个 AI 在 Unity 或 UE 中复现，由人评估还原度（布局、尺度、朝向、颜色），中间层方案应有明显提升。
- **MVP**：用户 10 分钟内能摆出一个小关卡的体块与语义，一键导出，AI 在引擎里复现出可行走、布局正确的灰盒关卡。

## 边界（暂定）

- 不做通用 3D 建模软件，不和 Blender / 引擎编辑器比功能。
- 不做资产生成本身，必要时调用现有 3D 生成 API（Meshy / Tripo / Hunyuan3D 等）。
- 先解决「意图传达」与「布局还原」，再谈美术质量。
